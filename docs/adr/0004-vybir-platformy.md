# ADR-0004. Вибір платформи цифрового двійника: Eclipse Ditto

## Статус

Прийнято, 2026-11-14

## Контекст

- Платформа має зберігати поточний стан двійника станції (reported / desired), приймати телеметрію й надавати API та події для вебподання (FR-01, FR-03, FR-05).
- Станція — об’єкт критичної інфраструктури; за поданням розгортання ЛР 1 платформа працює в ЦОД водоканалу, тобто має **розгортатися локально**.
- Телеметрія надходить зі шлюзу станції через **MQTT** (ЛР 1); бажано приймати її без проміжних сервісів.
- Масштаб невеликий: до 10 станцій, ≈ 272 повідомлення/с (NFR-03).
- Порівняння трьох платформ зваженою оцінкою з вагами, заданими до оцінювання, наведено в `docs/platform.md`, розділ «Порівняння платформ».

## Варіанти

1. **Eclipse Ditto** — відкрита платформа (EPL-2.0), модель W3C WoT Thing Model, вбудовані з’єднання MQTT / AMQP / Kafka / HTTP з відображенням формату; **S = 4,50**.
2. **Azure Digital Twins** — керований хмарний сервіс з моделями DTDL; найкраща масштабованість, але лише в хмарі Azure, а телеметрію треба доставляти через IoT Hub і Azure Functions; **S = 2,80**.
3. **Eclipse BaSyx** — відкрита реалізація AAS (MIT), локальне розгортання в Docker; для приймання телеметрії потрібен окремий компонент-міст; **S = 3,95**.

## Рішення

Обрано **варіант 1 — Eclipse Ditto 3.9.7**. Він єдиний задовольняє всі три найважливіші критерії одночасно: відкритий формат моделі, локальне розгортання й вбудоване приймання MQTT. На користь Ditto свідчить і джерело [3] у `sources.md`: відкрита платформа OpenTwins побудована саме на Ditto, з окремим сховищем часових рядів для історії.

## Наслідки

- **+** Повний контроль над даними й розгортанням у ЦОД водоканалу, без плати за кожну операцію.
- **+** Телеметрія з брокера надходить у Ditto напряму через з’єднання MQTT, а формат пристрою перетворюється відображенням JavaScript у домені зв’язку з пристроями (DCE) — це конфігурація гіпотези Г-01 з ЛР 1.
- **+** Ditto перевіряє кожну зміну стану за моделлю WoT і відхиляє значення поза діапазоном — додатковий рубіж якості даних (FR-02).
- **−** Експлуатацію кластера Ditto (13 контейнерів, MongoDB, оновлення) бере на себе служба ІТ водоканалу.
- **−** Ditto не зберігає історію станів, тому потрібне окреме сховище часових рядів. На навчальному стенді ЛР 2 це InfluxDB, як задано методичкою; рішення ADR-0001 щодо TimescaleDB для продуктивної платформи цим не змінюється.
- **−** Спільнота Ditto менша, ніж у хмарних постачальників, тож частину проблем доведеться розв’язувати самостійно.
